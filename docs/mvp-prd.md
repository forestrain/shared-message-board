# 交换心声 — MVP 产品需求文档（PRD）

## 1. 产品概述

### 1.1 名称与愿景

| 项 | 内容 |
|----|------|
| **产品名** | 交换心声 |
| **形态** | H5 Web 应用（移动端浏览器优先） |
| **一句话** | 用「板」承载话题，用「字」交换心情；可公开可私密，可个人可小组。 |

### 1.2 MVP 目标

验证以下闭环是否成立：

1. 创建留言板 → 留言 → 回复。
2. 公开 / 仅组内 / 私有（指定成员）三种可见性可控且不可越权访问。
3. 注册登录 → 创建或加入 Group → 组内可见留言板可用。

### 1.3 MVP 与后续版本边界（登录方式）

- **MVP 内**：手机号或邮箱注册 / 登录（验证码或密码，实现时二选一或组合以工程为准）。
- **MVP 之后**：微信登录、微信内一键授权、小程序壳等与微信生态深度集成的登录与身份能力。

本文档凡未列入「MVP 范围」的能力均视为非本阶段交付范围。

## 2. MVP 范围

### 2.1 In Scope（本阶段必做）

| 模块 | MVP 能力 |
|------|-----------|
| 账号 | 手机号或邮箱注册 / 登录；退出登录；基础资料（昵称；头像 URL 可选） |
| 留言板 | 创建板；标题 + 描述（可选）；可见性：**公开** / **仅组内** / **私有（指定成员）** |
| 留言与回复 | 发帖；针对帖子的**一层**回复（不做无限嵌套）；按时间排序 |
| Group | 创建组；通过**邀请码**加入组；组内成员列表对组员可见 |
| 权限 | 未登录：仅可浏览**公开板**列表与详情；登录后按板规则读写 |
| H5 | 响应式布局；主要适配手机浏览器 |

### 2.2 Out of Scope（本阶段不做）

| 项 | 说明 |
|----|------|
| **微信登录 / 微信 OAuth** | 放入 MVP 之后迭代，见第 8 节 |
| 富文本 | MVP 纯文本 + 换行 |
| 图片 / 语音 / 视频 | 不接上传；可预留扩展点 |
| 实时推送 | 无 WebSocket；列表与详情以刷新或轻量轮询为足 |
| 复杂审核与举报工单 | 不做；作者可删自己的帖/回复；板创建者可删板内任意内容（建议） |
| 付费、会员、广告 | 不做 |
| 原生 App | 仅 H5 |

### 2.3 关键产品决策

**私有板的「指定的人」**

- MVP 推荐：**仅从与板关联的同一 Group 成员** 中多选可见用户（降低账号关系与 ACL 复杂度）。
- 若某私有板不挂靠组：则须在 PRD 实施时明确「仅从好友列表选」或「强制私有板必须属于某组」——**建议 MVP：私有板若需指定成员，则必须属于某一 Group**，创建者在组员中勾选。

**Group 加入方式**

- MVP：**6 位（或类似）邀请码** 加入；不做审批流。

**板创建者与私有板**

- 板创建者**默认**对自己创建的私有板可见、可管理（避免「自己看不到自己的板」）。

## 3. 用户与场景

### 3.1 典型场景

- **私密**：仅少数朋友可见的树洞或话题 → 私有板 + 指定成员。
- **小组**：班级、兴趣组 → Group +「仅组内」板。
- **公开**：征友、活动公告 → 公开板。

### 3.2 核心用户旅程（MVP）

1. 使用手机号/邮箱完成注册与登录。
2. 创建 Group 或通过邀请码加入 Group。
3. 创建「仅组内」板，组员发帖与回复。
4. 创建「私有」板，在组员中勾选可见成员；非名单内用户不可见（列表与详情均不可访问）。
5. 浏览「公开」板；未登录可读公开内容；**发帖与回复须登录**（MVP 建议）。

## 4. 功能需求与验收标准

### 4.1 认证与账号

- 支持注册、登录、登出。
- 会话策略与实现见《architecture.md》；须防止未授权访问写接口。
- **验收**：新用户可注册并进入首页；在会话有效期内刷新页面保持登录态。

### 4.2 Group（小组）

- 登录用户可创建组；创建者为 **Owner**。
- 系统为组生成**邀请码**；用户凭邀请码加入为 **Member**。
- 组员可查看成员列表；**MVP 可选**：仅 Owner 将某成员移出组。
- **验收**：A 建组并展示邀请码；B 用邀请码加入后，两人在同一 `group_members` 关系下可查。

### 4.3 留言板（Board）

- 字段：**标题**、**描述（可选）**、**可见性**、**创建者**、**所属 Group**（当为「仅组内」或私有且策略要求挂靠组时必填）、**私有可见用户**（私有时）。
- 列表能力（MVP）：「我创建 / 我可访问的板」「公开广场」「我所在组的组内板」（需登录且为组员）。
- **验收**：三种可见性各至少一条用例；越权访问返回 **403**，响应体不泄漏板标题与正文。

### 4.4 留言（Post）与回复（Reply）

- 发帖：纯文本，建议上限如 2000 字。
- 回复：挂载在某一 Post 下，一层结构。
- 删除：作者删除自己的帖/回复；板创建者可删除该板下任意帖/回复（建议写入验收）。
- **验收**：时间序正确；删除后前后端数据一致。

### 4.5 权限矩阵（MVP 简化）

| 操作 | 未登录 | 登录非组员 | 组员 | 板创建者 | 私有名单用户 |
|------|--------|------------|------|----------|----------------|
| 读公开板 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 读组内板 | ✗ | ✗ | ✓ | 若同组 ✓ | 若同组 ✓ |
| 读私有板 | ✗ | ✗ | 未在名单 ✗ | ✓（默认） | ✓ |
| 发帖/回复 | ✗ | 按板规则 | 组内板需组员且板规则允许 | 按板规则 | 按板规则 |

具体「写权限」是否与「读权限」一致，MVP 建议：**能读且为登录用户则可发帖**，私有板仅名单用户与创建者可读则可写（可在实现时统一为同一 ACL）。

## 5. 非功能需求（MVP 底线）

- **安全**：所有写接口鉴权；所有读板/读帖接口按可见性与 ACL 校验；邀请码校验接口限流防暴力。
- **性能**：列表分页（cursor 或 offset）；单板帖子数量可设软上限或告警。
- **合规**：提供用户协议与隐私政策入口（可为静态页）；验证码防刷。
- **可观测（可选）**：请求日志、错误上报。

## 6. 里程碑建议

| 阶段 | 内容 |
|------|------|
| 第 1 段 | 账号（手机/邮箱）+ 公开板 CRUD + 帖子与一层回复 |
| 第 2 段 | Group + 邀请码 + 组内板 + 统一权限服务 |
| 第 3 段 | 私有板 + ACL + 越权与安全测试 + H5 体验与边界情况 |
| 第 4 段 | 联调、修缺陷、准备软发布 |

周期随人力在约 2～4 周量级浮动。

## 8. MVP 之后路线图（摘录）

以下能力不在 MVP 交付范围内，可作为排序 backlog：

1. **微信登录**：微信内 OAuth、开放平台移动应用或网站应用接入；与现有账号体系的绑定/合并策略。
2. 微信内分享卡片、小程序壳、订阅消息等微信生态能力。
3. 富文本、图片上传、@ 提醒、WebSocket 实时刷新。
4. 举报、审核后台、多管理员角色。
